BÀI TẬP 5: ĐẢM BẢO THỨ TỰ SỰ KIỆN VỚI KAFKA PARTITION KEY

Khóa học: Microservices System Design (Rikkei Education)
Hệ thống: Nền tảng E-Commerce StoreX
Topic: order-tracking (5 Partitions)
Công nghệ: Apache Kafka, Spring Kafka 3.x, MurmurHash2 Partitioner

1. Bối cảnh Nghiệp vụ & Thách thức Kiến trúc

Trong hệ thống StoreX, một đơn hàng di chuyển qua 3 giai đoạn then chốt trong vòng đời:

CREATED (Khởi tạo) → PAID (Đã thanh toán) → SHIPPED (Đang giao hàng)

Các sự kiện này được đẩy vào Kafka topic order-tracking. Topic được cấu hình có 5 Partitions để nhiều Consumer đọc song song nhằm gia tăng thông lượng.

Ràng buộc nghiêm ngặt: Các sự kiện của cùng 1 đơn hàng bắt buộc phải được xử lý theo đúng trình tự thời gian. Nếu hệ thống xử lý SHIPPED trước PAID, kho hàng sẽ xuất hàng cho một đơn hàng chưa thanh toán, gây thất thoát tài chính đặc biệt nghiêm trọng.

2. Phần 1 - Phân Tích Kỹ Thuật

2.1. Vì sao việc chia Partition làm mất thứ tự tổng thể của các sự kiện?

  • Nguyên tắc cốt lõi của Kafka: Apache Kafka không đảm bảo thứ tự toàn cục (Global Ordering) trên toàn bộ topic. Kafka chỉ đảm bảo thứ tự tuyệt đối bên trong từng Partition (Total Order within a Partition).
  • Trong một partition, các bản tin được ghi nối tiếp vào commit log với offset tăng dần. Nhưng khi topic được chia làm nhiều partition, mỗi partition được gán cho một Consumer thread độc lập.
  • Do sự chênh lệch về tốc độ xử lý giữa các thread, độ trễ mạng, hoặc GC pause, Consumer đọc partition này có thể xử lý nhanh hơn Consumer đọc partition khác. Nếu các sự kiện của cùng 1 đơn hàng bị rải rác sang các partition khác nhau, thứ tự xử lý sẽ bị đảo lộn hoàn toàn.

2.2. Minh họa bằng ví dụ cụ thể

Xét đơn hàng có orderId = 1001. Nếu Producer không chỉ định key (Round-robin):

  • Sự kiện 1: CREATED (10:00:00) → rơi vào Partition 0.
  • Sự kiện 2: PAID (10:00:05) → rơi vào Partition 2.
  • Sự kiện 3: SHIPPED (10:00:10) → rơi vào Partition 4.
Sự cố phát sinh: Consumer đang đọc Partition 2 bị nghẽn I/O Database trong 15 giây. Trong khi đó, Consumer đọc Partition 4 chạy rất nhanh, nhận và xử lý sự kiện SHIPPED vào lúc 10:00:11. Đến 10:00:20 Consumer 2 mới đọc tới PAID. Kết quả: Đơn hàng bị xuất kho trước khi thanh toán!

3. Phần 2 - Thiết Kế Giải Pháp Với Partition Key

3.1. Cơ chế Partition Key & Thuật toán MurmurHash2

Giải pháp triệt để là Producer bắt buộc phải gán partitionKey = String.valueOf(orderId) trong mọi bản tin gửi đi:

  • Thuật toán băm MurmurHash2: Kafka sử dụng hàm băm tất định (Deterministic Hashing) để tính toán partition đích:
    partition = Utils.toPositive(Utils.murmur2(keyBytes)) % 5
  • Tính nhất quán: Vì chuỗi key của đơn hàng là cố định (ví dụ "1001"), giá trị băm không bao giờ thay đổi. Do đó, toàn bộ 3 sự kiện CREATED, PAID, SHIPPED của đơn hàng #1001 luôn luôn được ghi vào cùng một Partition duy nhất.
  • Vì nằm trong cùng một partition, chúng chỉ được phục vụ bởi duy nhất 1 Consumer thread và được đọc tuần tự theo đúng thứ tự offset ban đầu.

3.2. Giải thích số lượng Consumer tối đa cho topic có 5 Partitions

Số lượng Consumer trong Group Cơ chế phân bổ Partition Đánh giá hiệu năng & Tài nguyên
1 Consumer 1 Consumer đọc toàn bộ 5 Partitions Không khai thác được xử lý song song; thông lượng thấp.
3 Consumers C1 đọc 2 partitions, C2 đọc 2 partitions, C3 đọc 1 partition Xử lý song song mức trung bình.
5 Consumers (TỐI ƯU NHẤT) Mỗi Consumer phụ trách chính xác 1 Partition Đạt thông lượng tối đa (Max Throughput), tải cân bằng tuyệt đối.
6 Consumers trở lên 5 Consumer đọc 5 Partitions, các Consumer còn lại IDLE LÃNG PHÍ TÀI NGUYÊN! Consumer thứ 6 không có partition nào để đọc (ở trạng thái chờ/dự phòng).
Kết luận cấu hình: Trong Apache Kafka, một partition không bao giờ được gán cho nhiều hơn 1 consumer trong cùng một Consumer Group. Do đó, số lượng Consumer tối đa có hiệu lực luôn bằng số lượng Partitions (= 5 Consumers).

4. Phần 3 - Mã Nguồn Cài Đặt

4.1. Topic Configuration (`KafkaTopicConfig.java`)

@Configuration
public class KafkaTopicConfig {

    public static final String ORDER_TRACKING_TOPIC = "order-tracking";
    public static final int TOTAL_PARTITIONS = 5;

    @Bean
    public NewTopic orderTrackingTopic() {
        return TopicBuilder.name(ORDER_TRACKING_TOPIC)
                .partitions(TOTAL_PARTITIONS)
                .replicas(1)
                .build();
    }
}

4.2. Producer Gửi Với Partition Key (`OrderTrackingProducer.java`)

@Service
@Slf4j
@RequiredArgsConstructor
public class OrderTrackingProducer {

    private final KafkaTemplate<String, OrderTrackingEvent> kafkaTemplate;

    public CompletableFuture<SendResult<String, OrderTrackingEvent>> sendTrackingEvent(OrderTrackingEvent event) {
        // Ép toàn bộ sự kiện của cùng đơn hàng vào cùng partition bằng orderId làm key
        String partitionKey = String.valueOf(event.getOrderId());

        log.info("Producer gửi sự kiện [orderId={}, status={}] với Partition Key=[{}]",
                event.getOrderId(), event.getStatus(), partitionKey);

        return kafkaTemplate.send(KafkaTopicConfig.ORDER_TRACKING_TOPIC, partitionKey, event);
    }
}

4.3. Consumer Kiểm Soát Thứ Tự (`OrderTrackingConsumer.java`)

@Service
@Slf4j
public class OrderTrackingConsumer {

    private final ConcurrentHashMap<Long, OrderStatus> orderCurrentState = new ConcurrentHashMap<>();

    // Concurrency = 5: Tối đa 5 consumer threads tương ứng 5 partitions
    @KafkaListener(topics = "order-tracking", groupId = "order-tracking-group", concurrency = "5")
    public void consume(
            ConsumerRecord<String, OrderTrackingEvent> record,
            @Header(KafkaHeaders.RECEIVED_PARTITION) int partition,
            @Header(KafkaHeaders.OFFSET) long offset) {

        OrderTrackingEvent event = record.value();
        validateAndProcessStatusTransition(event.getOrderId(), event.getStatus(), partition, offset);
    }

    public synchronized void validateAndProcessStatusTransition(Long orderId, OrderStatus newStatus, int partition, long offset) {
        OrderStatus currentStatus = orderCurrentState.get(orderId);
        if (currentStatus == null) {
            if (newStatus != OrderStatus.CREATED) {
                throw new IllegalStateException("Lỗi thứ tự: Đơn hàng " + orderId + " nhận " + newStatus + " khi chưa có CREATED");
            }
            orderCurrentState.put(orderId, OrderStatus.CREATED);
            return;
        }

        if (currentStatus == OrderStatus.CREATED && newStatus == OrderStatus.PAID) {
            orderCurrentState.put(orderId, OrderStatus.PAID);
        } else if (currentStatus == OrderStatus.PAID && newStatus == OrderStatus.SHIPPED) {
            orderCurrentState.put(orderId, OrderStatus.SHIPPED);
        } else {
            throw new IllegalStateException("Lỗi thứ tự: Chuyển đổi trạng thái bất hợp lệ từ " + currentStatus + " sang " + newStatus);
        }
    }
}
